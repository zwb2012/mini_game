# 场景管理器 (Scene Manager)

> **Status**: In Design
> **Author**: game-designer + Claude
> **Last Updated**: 2026-05-20
> **Implements Pillar**: 间接服务全部支柱——场景是物理谜题的容器

## Summary

场景管理器负责关卡房间的加载、卸载、重置和过渡。它根据游戏状态机的指令切换场景——从主菜单到第一关、从当前房间到下一房间、死亡后重置当前房间。作为 Core 层系统，它不定义"房间里有什么"（那是关卡设计数据系统的职责），只负责"何时加载哪个场景"和"过渡怎么播"。

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `游戏状态机`

## Overview

场景管理器是关卡结构的运行时执行者。它将关卡设计数据系统提供的场景配置实例化为可玩的游戏场景，管理场景之间的过渡（淡入淡出/加载画面），并在玩家死亡时重置当前房间的物理状态。MVP 阶段支持 3 个战斗房间 + 1 个 Boss 房间的线性推进。

## Player Fantasy

场景管理器是基础设施——玩家不直接感知它。它的成功表现为**关卡推进的流畅感**：清空房间后无缝过渡到下一个房间，死亡后瞬间重置到房间起点。**一句话幻想**：让关卡流动起来，不让玩家等待加载。

## Detailed Design

### Core Rules

1. **场景粒度**：每场战斗房间是一个独立场景（Godot `.tscn` 文件）。Boss 房间也是独立场景。过渡区域（走廊/喘息点）可以是独立场景或房间场景的一部分。

2. **场景加载模式**：
   - 顺序推进（正常游戏）：当前场景 → 卸载 → 加载下一场景
   - 死亡重置（DEAD → PLAYING）：重新加载当前场景（或调用场景内重置方法）
   - 菜单跳转（MAIN_MENU → PLAYING）：加载指定关卡

3. **过渡效果**：场景切换时播放过渡动画——淡入淡出（默认 300ms）。死亡重置无过渡动画（瞬切，保持死亡画面的视觉连续性）。

4. **场景状态保存**：死亡重置时，场景恢复到初始配置（所有敌人重生、物理要素重置）。不使用 Godot 的 `PackedScene` 重新实例化——而是调用场景根节点的 `reset()` 方法（更高效，避免重新加载资源）。

5. **MVP 场景清单**：

| 场景 ID | 类型 | 说明 |
|---------|------|------|
| `main_menu` | 菜单 | MVP 可选——无菜单时直接跳到 room_1 |
| `room_1` | 战斗房间 | 教学——单一物理要素（油桶） |
| `room_2` | 战斗房间 | 组合——油桶 + 悬挂物 |
| `room_3` | 战斗房间 | 进阶——油桶 + 悬挂物 + 可破坏墙 + 酸液池 |
| `boss_1` | Boss 房间 | 终极物理谜题 |

### States and Transitions

| 状态 | 含义 | 触发条件 |
|------|------|----------|
| **IDLE** | 无场景加载中 | 系统初始化后 |
| **LOADING** | 场景加载/卸载进行中 | 收到加载请求 |
| **ACTIVE** | 场景已加载并运行中 | 加载完成 |
| **RESETTING** | 当前场景重置中 | 玩家死亡 |

### Interactions with Other Systems

| 目标系统 | 方向 | 交互 |
|----------|------|------|
| 游戏状态机 | 上游 | 根据 `state_changed` signal 触发场景操作（PLAYING→DEAD=重置，LEVEL_COMPLETE→PLAYING=下一关） |
| 关卡设计数据系统 | 上游 | 读取场景配置（哪个 ID 对应哪个 .tscn，房间内有什么） |
| 死亡与重生系统 | 上游 | 死亡时请求场景重置 |
| 2D 摄像机系统 | 下游 | 场景加载后设置摄像机边界 |
| 敌人生成与波次管理 | 下游 | 场景加载后触发生成 |

## Formulas

无数学公式。场景切换是资源管理操作。

## Edge Cases

- **场景加载文件不存在**: 回退到错误场景（`error.tscn` 或直接显示错误文本）。不可静默失败。
- **快速连续触发场景切换（如玩家在加载中死亡）**: 队列化——当前加载完成后立即执行下一个请求。队列深度上限 = 2，超出时丢弃最早的队列请求。
- **最后一个房间通关后无下一场景**: 触发 `LEVEL_COMPLETE` → `MAIN_MENU` 过渡。MVP 阶段可能直接显示"恭喜通关"文本。
- **场景加载超时（>5 秒）**: 显示加载失败提示，允许玩家返回主菜单。
- **设备内存不足导致加载失败**: 尝试卸载当前场景后再加载新场景（而非同时加载）。如果仍然失败，降低纹理/音频质量后重试。

## Dependencies

| 系统 | 方向 | 依赖性质 |
|------|------|----------|
| **游戏状态机** | 上游（本系统依赖它） | 硬依赖——状态切换驱动场景操作 |
| **关卡设计数据系统** | 上游（本系统依赖它） | 硬依赖——需要知道加载哪个场景 |
| **2D 摄像机系统** | 下游（依赖本系统） | 硬依赖——场景加载后需设置摄像机边界 |
| **敌人生成与波次管理** | 下游（依赖本系统） | 软依赖——场景加载后触发生成 |
| **死亡与重生系统** | 上游（触发本系统） | 硬依赖——死亡时请求场景重置，本系统执行重置 |

## Tuning Knobs

| 参数 | 默认值 | 安全范围 | 说明 |
|------|--------|----------|------|
| `transition_duration_ms` | 300 | 100~1000 | 场景切换淡入淡出时长 |
| `load_timeout_ms` | 5000 | 3000~15000 | 加载超时阈值 |

## Visual/Audio Requirements

场景管理器本身无视觉/音频输出。过渡动画（淡入淡出）是简单的全屏颜色覆盖，不涉及复杂特效。

## UI Requirements

加载画面可包含简单的关卡名称文本（Alpha 阶段添加）。MVP 阶段仅黑屏过渡。

## Acceptance Criteria

- [ ] **AC1**: GIVEN 游戏状态从 MAIN_MENU 切换到 PLAYING，WHEN 场景管理器响应，THEN 加载 room_1 场景
- [ ] **AC2**: GIVEN 玩家在 room_1 清空所有敌人，WHEN 触发通关条件，THEN 卸载 room_1、加载 room_2
- [ ] **AC3**: GIVEN 玩家在 room_2 死亡，WHEN 状态切换到 DEAD 后选择重生，THEN room_2 重置到初始状态（所有敌人重生、物理要素复位）
- [ ] **AC4**: GIVEN 场景加载进行中，WHEN 检查过渡效果，THEN 显示淡入淡出动画（默认 300ms）
- [ ] **AC5**: GIVEN 最后一个房间（boss_1）通关，WHEN 触发 LEVEL_COMPLETE，THEN 过渡到结算画面或主菜单
- [ ] **AC6**: GIVEN 场景文件不存在或加载失败，WHEN 超时 5 秒后，THEN 显示错误提示并允许返回主菜单
- [ ] **AC7**: GIVEN 当前场景正在加载中，WHEN 第二个加载请求到达，THEN 请求排队，当前加载完成后执行
- [ ] **AC8**: **性能**: 场景加载（卸载旧+加载新）≤ 2 秒（在目标中端设备上）
- [ ] **AC9**: 场景 ID 与 .tscn 文件路径的映射从配置文件读取，无硬编码
