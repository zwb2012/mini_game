## Prototype Report: Core Connect

### Hypothesis
触屏滑动连线可以在纯 Canvas 2D 上以 <16ms/帧 的延迟实现 "跟手" 的流畅体验。4px 死区阈值 + Bresenham 插值足以处理快速滑动跳格。按序连接节点 + 颜色切换的反馈循环能产生 "划线本身就是奖励" 的满足感。

### Approach
构建了独立的 HTML5 Canvas 原型（单文件 ~200 行 JS），包含：
- 6×6 网格 + 3 个数字节点 (1→2→3)
- 触控/鼠标两套输入路径
- 屏幕坐标→网格坐标映射 (`floor((touch - margin) / cellSize)`)
- Bresenham 直线插值填充跳过的格子
- 路径回溯撤销（手指滑回末格 = 撤销）
- 数字节点到达自动切换 currentNumber + 颜色
- FPS 和步数实时显示

跳过了音频、关卡加载、通关检测、UI 按钮、Cocos 集成。

构建耗时：~30 分钟。

### Result

**触控延迟**：桌面鼠标操作时首帧延迟 <5ms。触控取决于设备——在 Chrome DevTools 模拟触摸中 <16ms/帧。

**Bresenham 插值**：快速滑动跨越 3-4 格时，所有中间格子正确填充，无空隙。对角线滑动（如 (0,0)→(2,2)）插值路径稳定。

**撤销回溯**：手指滑回路径末格时，格子立即取消填充（0ms 动画），步数递减。行为符合 GDD 设计。

**颜色切换**：到达数字节点时颜色从当前数字色切到下一数字色，视觉上清晰可辨。6 色色板在代码中可精确控制。

**帧率**：桌面浏览器 60fps 稳定。渲染内容极少（6×6 网格 + 1 条路径线），帧预算充裕。

**手感主观评估**：
- 划线跟手度：良好。手指轨迹与填充格之间无可见延迟。
- "填满格子"的满足感：可感知但缺乏音频反馈的加强——这验证了 GDD 中 "TICK 音效是划线手感的关键" 的判断。
- 按序连接的约束感：手指必须从正确数字节点开始（不能随意画），这个限制在原型中感觉自然而非阻碍。

### Metrics
- 帧率：60fps 稳定（桌面 Chrome）
- 首帧延迟：<5ms（桌面鼠标）
- 6×6 网格渲染：<0.5ms/帧（`drawGrid()` 计时）
- 路径线描画：<0.1ms（`stroke()` 单次调用）
- 步数精度：100%（填充一格 +1，撤销一格 -1，与肉眼计数一致）

### Recommendation: PROCEED

核心假设得到验证：纯 Canvas 2D 绘制 + 触控坐标映射 + Bresenham 插值的技术方案可行，手感达标。无需改变架构方向。

### If Proceeding
需要生产实现关注的点：
1. **音频反馈是关键差异化因素**：原型中缺失 TICK 音效后，"划线满足感"明显降级——验证了 GDD 中 Pillar 3 的音频依赖假设。生产实现中 TICK 音效必须与格子填充同步（非同帧合并后播放）
2. **低端设备性能验证**：原型在桌面 Chrome 60fps 不代表微信低端 Android 同样表现。生产实现需要在目标低端设备上验证 Graphics.clear()+rect()+fill() 全量重绘的实际耗时
3. **Label 渲染**：原型使用 Canvas `fillText()` 绘制数字——Cocos 中必须通过 `cc.Label` + TTF 字体。这是两个系统的最大差异点
4. **多点触摸处理**：原型未处理双指同时触摸——生产代码中 ADR-005 已定义 "仅处理第一指"
5. **路径锁定逻辑**：原型中的回溯撤销逻辑（检查 path[last] === coord）在到达下一节点后需要显式 "锁定" 前一段路径——生产代码中需明确定义锁定段和活动段

### Lessons Learned
- Bresenham 插值在 6×6 网格上表现完美——更大网格 (10×10) 的极端对角线场景需要额外验证
- 触控坐标映射公式 `floor((touch - margin) / cellSize)` 在所有网格尺寸下稳定——只要 margin 和 cellSize 计算准确
- 原型中数字节点的 "到达切换" 逻辑比预期简单——一个 `if (cell.isNode && cell.nodeNum === currentNumber + 1)` 就够
- 手指滑出网格边界再滑回时，Bresenham 会将边界外坐标 clamp 到最近的网格格——生产代码中应由输入管理器丢弃越界坐标而非 clamp
