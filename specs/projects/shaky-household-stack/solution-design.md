# 项目
- 名称：摇晃桌面叠物
- 标识：shaky-household-stack

# 实现目标
- 本阶段目标：把架构拆成清晰、可实现、可测试的开发子方案，明确模块边界与先后顺序

# 方案拆分
- 子方案 1：单局状态机与物体投放系统
- 子方案 2：桌面摇晃与失稳判定系统
- 子方案 3：结算、复活、广告与埋点接入

# 接口与边界
- 输入：玩家放置操作、物体配置、广告回调、局内状态事件
- 输出：分数、层数、是否倒塌、是否允许复活、局后埋点事件
- 依赖：物理参数配置、UI 反馈资源、广告和埋点接口封装

# 实施顺序
- 第一步：先完成单局状态机与放置反馈，验证玩法闭环可跑通
- 第二步：接入失稳判定和倒塌结算，验证失败反馈是否成立
- 第三步：再接入复活、广告和埋点，避免商业化逻辑提前干扰玩法验证

# 风险与回退
- 主要风险：如果失稳判定过于随机，会降低玩家对结果的信任感
- 回退策略：若完整摇晃桌面方案体验不稳定，可暂时改为“周期性倾斜 + 简化重心检测”版本先保住可玩性
