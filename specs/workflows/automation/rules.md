# 自动化流水线运行规则

## 一、总则
1. 所有项目都通过单一总控入口推进，不要求用户手动逐个调用叶子技能。
2. 总控入口只负责调度、校验、门禁与停止判断，不负责替代阶段产出本身。
3. 每个阶段必须有唯一主产物文件，禁止多个文档重复表达同一结论。
4. 所有文档型产物默认使用中文输出；仅在代码、API 名称、第三方库名、字段键名与必要英文术语处保留英文。
5. 候选层先读取 `portfolio/candidate-score-rules.yaml`，正式项目层先读取 `portfolio/project-thresholds.yaml`，再决定是否前进。

## 二、组合层规则
### 1. 多项目并行
- 允许多个项目同时存在于组合层。
- 但高投入阶段必须受 WIP 限制。

### 2. WIP 限制
- researching：最多 5 个
- prd_draft：最多 2 个
- architecture / solution_design / uiux：总计最多 2 个
- implementation：最多 1 个
- test / acceptance / launch_prep：总计最多 2 个

### 3. 优先级原则
优先级默认按以下顺序判断：
1. 用户已选主方向的项目
2. 距离 `submission_ready` 最近的项目
3. 用户价值验证证据最强的项目
4. 实施成本最低、可快速形成闭环的项目

## 三、阶段推进规则
1. 进入下一个阶段前，必须校验当前阶段产物是否存在。
2. 若当前阶段产物字段不完整，不允许推进。
3. 候选层 `threshold_result` 为 `promote` 时才进入正式项目；为 `hold` 或 `reject` 时停留或退出候选层。
4. 正式项目层 `threshold_result` 为 `pass` 时才继续前进；为 `hold / fail / rework` 时必须停住并按结果分流。
5. 若阶段需要人工门禁，必须停住并等待确认。

## 四、质量优先规则
1. 流水线的目标不是“尽快做完”，而是“更快筛对方向”。
2. 调研、PRD、测试、验收阶段必须显式回答“用户是否会买账”。
3. 任何无法支撑用户价值判断的产物，都不能视为合格完成。

## 五、仓库边界规则
### 模板仓库
保存：
- 工作流规则
- 阶段模板
- 通用 skill
- 子代理 prompt 规范

### 项目仓库
保存：
- 具体产品代码
- 具体产品文档
- 资源文件
- 构建与测试产物

### 组合层仓库
保存：
- 多项目状态
- 索引与优先级
- WIP 规则
- 决策记录

## 六、禁止事项
- 不允许自动越过方向选择、PRD 审批、提审包完成三个门禁
- 不允许在没有明确停止条件的情况下无限重试
- 不允许自动发起真实微信提审动作
- 不允许在文档中主要使用英文说明
